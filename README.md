# Shade Client

Расширение для браузеров на базе Chromium и Firefox. Подключается к Shade Server по URL и паролю, сохраняет профили сайтов и позволяет управлять доступом.

## Установка

Готовые сборки находятся в разделе **Releases**. Для установки не нужны Node.js, Python или терминал.

### Chromium (Chrome, Brave, Vivaldi и другие)

1. Скачайте `shade-chromium.zip` и распакуйте архив в постоянную папку.
2. Откройте `chrome://extensions` (или страницу расширений своего браузера).
3. Включите режим разработчика и нажмите «Загрузить распакованное расширение».
4. Выберите папку `shade-client` с файлом `manifest.json`.

Если браузер разрешает установку расширений из сторонних источников, можно вместо ZIP скачать `shade-chromium.crx` и открыть его через страницу расширений. Подписанный CRX не отменяет ограничений браузера: в частности, обычный Chrome на Windows и macOS может потребовать установку из Chrome Web Store. В этом случае используйте ZIP.

### Firefox (140 и новее)

1. Скачайте подписанный `shade-firefox.xpi`.
2. Откройте `about:addons`, нажмите значок шестерёнки и выберите «Установить дополнение из файла».
3. Укажите скачанный XPI и подтвердите установку.

Файл `shade-firefox-unsigned.xpi` из Actions предназначен только для тестирования. В обычном Firefox постоянная установка требует подписи Mozilla. Совместимость с отдельными форками Firefox, приватными окнами, контейнерами и нестандартной изоляцией cookies не гарантируется; используйте обычный профиль браузера.

## Использование

Откройте Shade, нажмите «+ Сайт», введите URL и пароль, затем разрешите доступ к выбранному сайту. Сохранённые профили можно открывать из списка и отключать по отдельности или все сразу. После истечения сессии потребуется повторный ввод пароля. Пароль не сохраняется.

Для удалённых серверов требуется HTTPS. При неудачной авторизации открывается публичная версия сайта.

## Обновление

Для ZIP замените файлы в прежней папке и нажмите «Обновить» на странице расширений. Для CRX или XPI установите новый файл поверх предыдущей версии. Не удаляйте расширение перед обновлением, если требуется сохранить профили. Установка CRX вместо ранее распакованного ZIP может создать отдельное расширение с другим ID. Автоматическое обновление с GitHub пока не настроено.

## Данные и разрешения

Профили хранятся локально. Расширение запрашивает доступ только к указанным пользователем сайтам. Данные авторизации и сессионный токен используются для подключения к выбранному серверу; пароль не передаётся и не сохраняется. Телеметрии и передачи данных разработчику нет. Управление cookies необходимо для работы сеансов.

## Сборка из исходников

Требуется Node.js 22+ и npm.

```sh
npm install
npm test
npm run build
```

Результат: `dist/chromium/` и `dist/firefox/`. Для сборки только одного варианта используйте `npm run build -- chromium` или `npm run build -- firefox`.

Для временного тестирования Firefox откройте `about:debugging#/runtime/this-firefox` и загрузите `dist/firefox/manifest.json`. Исходники из `src/` напрямую не устанавливаются.

## Публикация релизов

GitHub Actions собирает и тестирует обе версии. При публикации релиза ZIP прикрепляется автоматически, CRX и подписанный XPI — при наличии ключей. Подготовка ключей выполняется владельцем репозитория один раз.

### CRX

Создайте постоянный RSA-ключ (нужен OpenSSL):

```sh
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out shade-crx.pem
```

В **Settings → Secrets and variables → Actions → New repository secret** добавьте `CRX_PRIVATE_KEY` с полным содержимым PEM-файла. Храните резервную копию ключа вне репозитория. Не меняйте его между релизами: от ключа зависит ID расширения.

### Firefox

Создайте аккаунт [Mozilla Add-ons](https://addons.mozilla.org/developers/) и получите [API credentials](https://addons.mozilla.org/developers/addon/api/key/). Добавьте в GitHub Secrets:

- `AMO_JWT_ISSUER` — JWT issuer;
- `AMO_JWT_SECRET` — JWT secret.

ID Firefox задаётся в `tools/manifests.mjs`. Не меняйте его после первого подписания. При первой публикации подтвердите соглашения Mozilla, если потребуется. Подписание выполняется через `web-ext sign --channel unlisted`, без публикации в каталоге AMO. На проверку отправляется также архив исходников с инструкциями сборки и lock-файлом.

### Выпуск новой версии

Измените версию в `package.json` и `src/manifest.json`. Если в репозитории уже есть `package-lock.json`, обновите и его (`npm install --package-lock-only`). Создайте тег на новом коммите и опубликуйте Release. Например, `v0.10.0`. Простое выполнение Run workflow создаёт тестовые артефакты, но не публикует релиз.

Файлы релиза: `shade-chromium.zip`, `shade-chromium.crx`, `shade-firefox.xpi`. Задачи публикации независимы: отказ в подписи Mozilla не мешает публикации Chromium. Если проверка Mozilla занимает больше времени, подписанный XPI можно скачать из Developer Hub после её завершения и вручную прикрепить к релизу. Не отправляйте ту же версию повторно, если она уже находится на проверке.
